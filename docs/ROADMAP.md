# 多轮搜索问答强化学习复现路线图

## 目标
复现“Wikipedia + BM25 多轮搜索问答、SFT 冷启动、DAPO/GRPO 强化学习优化”的完整闭环，并记录可用于面试的工程与算法决策。实验结果以本项目实际运行结果为准，不要求与参考项目数值完全一致。

## 总体阶段

### 0. 项目准备
- 固定 Python、CUDA、PyTorch、Transformers、vLLM、veRL 版本。
- 建立配置、日志、checkpoint、数据和评估目录。
- 确认 GPU 显存、磁盘空间和下载方式。

### 1. 数据与检索环境
- 下载 HotpotQA、NQ，必要时加入 Bamboogle。
- 获取 Wikipedia 2018 处理语料。
- 用 BM25 建立离线索引并实现 `search(query, top_k)` API。
- 编写检索单元测试：空查询、重复查询、未命中、top-k 排序。

### 2. 基线系统
- 实现单轮 RAG 和多轮 ReAct/Tool-Use 推理循环。
- 先用 Qwen2.5-3B/7B Instruct 验证工具调用格式。
- 记录 EM、F1、平均检索次数、无效调用率和答案完成率。

### 3. SFT 冷启动
- 使用较强 Teacher 生成多轮搜索轨迹。
- 按格式、工具调用有效性、答案正确性和轨迹长度过滤。
- 先用小规模数据验证，再扩展到约 15,000 条。
- 对学生模型进行 LoRA/全参数 SFT，保存数据版本和 checkpoint。

### 4. 强化学习
- 先实现 outcome reward 的 GRPO 基线。
- 加入搜索次数/额外搜索惩罚，验证成本敏感奖励。
- 再接入 DAPO；实现动态采样、裁剪策略和训练稳定性监控。
- 最后实现过程级 advantage/credit assignment，并做消融实验。

### 5. 评估与分析
- 在 HotpotQA、NQ、Bamboogle 等固定测试集上评估。
- 对比 Base、SFT、GRPO、成本奖励、DAPO、过程级奖励。
- 绘制准确率—检索成本曲线，分析失败轨迹和奖励崩溃案例。
- 整理最终实验表格和面试讲解材料。

## 推荐的降级路线
先用 Qwen2.5-1.5B/3B、HotpotQA 子集、BM25 和 LoRA 跑通闭环；再逐步扩大数据、模型和训练规模。资源不足时优先保证流程、奖励和评估可解释，而不是追求原项目规模。

每个阶段都必须提交：配置文件、运行命令、日志路径、数据版本、checkpoint（如有）、评估结果和已知问题。任何结果都记录随机种子、硬件和代码版本。
